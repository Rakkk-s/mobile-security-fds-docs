# 큐싱 기반 드로퍼 · 적용 룰

정식 마켓 드로퍼가 지연 투하로 악성 모듈을 꺼내고, 접근성 주입으로 **피해자 본인 단말에서 직접 이체**한다. 공통 룰 27개 중 **10개가 발화**한다(핵심 8 · 보조 2). 본인 단말·본인 IP라 위치 기반 탐지가 통째로 무력해, 오버레이·접근성·입력 방식이 판정을 떠맡는다.

## 타임라인별 대응

| 시점 | 공격 행위 | 발화 룰 | 적용 정책 |
| --- | --- | --- | --- |
| **T1** | 악성 QR 살포 → 피해자가 스캔해 단축 URL 접속 | [R-02](rule-catalog.md#r-02) ([R-01](rule-catalog.md#r-01) 조건부) | 모니터링 |
| **T2** | 리다이렉트 경유 정식 마켓 드로퍼 설치 | [R-02](rule-catalog.md#r-02) | 모니터링 |
| **T3** | 드로퍼가 품고 있던 페이로드를 꺼내 설치 (지연 투하) | [R-03](rule-catalog.md#r-03) · [R-04](rule-catalog.md#r-04) | **거래 보류** |
| **T4** | 접근성 권한 요청·허용 | [R-08](rule-catalog.md#r-08) | 모니터링 |
| **T5** | 금융앱 위 오버레이 + 화면 캡처·미러링 | [R-13](rule-catalog.md#r-13) ([R-12](rule-catalog.md#r-12) 조건부) | 아웃바운드 콜 |
| **T6** | 알림 차단 + 이체한도 상향 조작 | [R-15](rule-catalog.md#r-15) | 모니터링 |
| **T7** | 접근성 주입으로 피해자 단말에서 직접 이체 | [R-19](rule-catalog.md#r-19) · [R-20](rule-catalog.md#r-20) | **거래 보류** |
| **T8** | 자금세탁 + 악성앱 삭제·예외 등록으로 흔적 제거 | — | 공백(의도) |

여러 룰이 동시에 걸리면 가장 강한 정책을 적용한다.

```
거래 보류  >  아웃바운드 콜  >  추가 인증  >  모니터링
```

**T3에서 이미 거래 보류가 가능하다.** 이체가 실행되는 T7보다 4단계 앞선다.

**T2에 설치 자체를 잡는 룰이 없다.** 드로퍼가 정식 마켓을 통과해 미확인 경로로 안 잡히고, 이 시점엔 악성 기능이 없어 확진도 침묵한다. 페이로드 실체가 드러나는 T3에서 두 룰이 받는다. T8의 흔적 제거는 발화 룰을 두지 않고 증거 보존과 사후 절차가 담당한다.

## 발화 근거

시점마다 어떤 데이터가 걸려 그 정책이 나오는지 정리한다. 데이터 이름을 누르면 정의로 이동한다.

| 시점 | 걸리는 데이터 | 판정 이유 |
| --- | --- | --- |
| **T1** | [URL 검사(직접)](detection-device.md#thr-r-url-scan) · [도메인 등록 경과일](detection-device.md#thr-r-domain-age) · [리다이렉트 횟수](detection-device.md#thr-r-hops) · [리다이렉트 최종 도착지](detection-device.md#thr-r-final-url) | 신생 도메인이라 위험목록에 없어 등재 판정이 침묵한다. 대신 도메인이 등록된 지 30일이 안 됐고 리다이렉트가 3회 이상 겹쳐 최종 목적지를 감춘 정황으로 잡는다. QR이 문자로 살포된 경우에만 사칭 문자 룰이 주소록 미등록 조건으로 부분 발화한다 |
| **T2** | [설치 주체](detection-device.md#thr-i-installer) | 설치 주체가 정식 마켓이다. 미확인 경로가 아니라 사칭 분류 룰이 침묵하고, 이 시점 드로퍼에는 악성 기능이 없어 확진도 안 된다. 설치 자체를 잡는 룰이 없는 구간이며 도메인 정황만 남는다 |
| **T3** | [악성코드 유형](detection-device.md#av-type) · [인증서 해시](detection-device.md#thr-i-cert) · [설치 주체](detection-device.md#thr-i-installer) | 드로퍼가 품고 있던 페이로드를 로컬에 떨어뜨려 설치하므로 이때 미확인 경로로 잡힌다. 페이로드가 트로이목마로 확진되고 서명 인증서가 블랙 목록과 일치해 확정 신호 두 개가 동시에 성립한다 |
| **T4** | [과다 권한 목록](detection-device.md#thr-i-perms) · [접근성 서비스 활성 여부](detection-device.md#thr-r-a11y) | 접근성 권한을 갖고 실제 활성 상태다. 다만 스크린리더 같은 정당 용례가 있어 보류하지 않고, 이 시점부터 세션을 접근성 활성으로 표시해 이후 룰의 가중 조건으로 쓴다 |
| **T5** | [오버레이 활성 여부](detection-device.md#thr-r-overlay) · [화면 캡처·미러링 활성 여부](detection-device.md#thr-r-capture) · [마지막 사용 시각](detection-device.md#thr-i-last-used) | 오버레이와 화면 캡처가 동시에 도는 것은 정상 앱 사용에 없는 조합이다. 화면 필터는 녹화하지 않고 화면 공유는 금융앱 위에 창을 띄우지 않는다. 가린 주체를 알 수 없으므로 그 시각에 쓰이던 위협앱을 주체로 추정한다. 원격 지원 상담 가능성이 남아 통화로 확인하고, 오버레이가 30초를 넘기면 거래 보류로 상향한다 |
| **T6** | [이체한도 변경 시각](detection-financial.md#fin-limit-time) · [이체한도 상향 배수](detection-financial.md#fin-limit-ratio) · [마지막 사용 시각](detection-device.md#thr-i-last-used) | 알림 차단 자체는 관측할 데이터가 없어 한도 상향 정황으로 대체한다. 위협앱이 구동 중인 5분 창 안에서 한도가 5배 이상 올라간 것은 정상 사용자의 상향 패턴과 다르다. 단독 조치는 하지 않고 세션 위험도만 올려 둔다 |
| **T7** | [이체 입력 발생 방식](detection-financial.md#fin-input-source) · [위협 앱 분류](detection-device.md#thr-i-category) · [접근성 서비스 활성 여부](detection-device.md#thr-r-a11y) · [신규 수취인 여부](detection-financial.md#fin-new-payee) | 이체 입력에 대응하는 물리 터치가 없다. 사람은 화면을 만지지 않고 입력할 수 없으므로 주입은 정황이 아니라 증명이다. 미확인 경로 앱의 접근성이 켜진 상태에서 신규 수취인으로 이체가 나가 접근성 조작 룰도 함께 걸린다. 접근성 조작 룰은 아웃바운드 콜이지만 주입 증명이 함께 발화해 최종 정책은 거래 보류가 된다 |

| [R-26](rule-catalog.md#r-26) | 본인 단말·본인 IP에서 이체가 일어나 위치 모순이 없다 — 이 시나리오의 핵심 구멍이다 |

**이 시나리오의 최대 특징은 기기·위치 불일치가 침묵한다는 것이다.** 다른 세 시나리오에서 강력한 마지막 방어선인데, 온디바이스 이체는 본인 단말에서 일어나 이 신호가 아예 생기지 않는다. 그 공백을 접근성 조작과 비인간 입력이 대신 받는다. 설치 단계도 정식 마켓 경유라 한 겹 얇아, 판정의 무게가 은폐·거래 단계로 몰린다.
