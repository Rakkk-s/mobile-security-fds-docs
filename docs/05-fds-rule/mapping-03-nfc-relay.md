# NFC 릴레이 공격 · 적용 룰

보이스피싱으로 최소권한 리더 앱을 깔게 하고, 실물 카드를 태그하게 유도해 카드 응답을 원격지 ATM까지 실시간 중계한다. 공통 룰 27개 중 **8개가 발화**한다(핵심 7 · 보조 1). 권한이 거의 없어 권한 기반 탐지가 오히려 무력한 역설이 있고, 태그 지속 시간과 기기·위치 불일치가 판정의 축이 된다.

## 타임라인별 대응

| 시점 | 공격 행위 | 발화 룰 | 적용 정책 |
| --- | --- | --- | --- |
| **T1** | 저금리 대환대출 미끼로 장시간 통화 유인 | — | 공백(의도) |
| **T2** | 가짜 구글플레이 스토어 페이지 접속 | [R-02](rule-catalog.md#r-02) | 모니터링 |
| **T3** | 은행 사칭 보안인증 앱 설치 | [R-04](rule-catalog.md#r-04) ([R-05](rule-catalog.md#r-05) 조건부) | **거래 보류** |
| **T4** | NFC·인터넷 두 개 권한만 요청·허용 | [R-09](rule-catalog.md#r-09) | 추가 인증 |
| **T5** | 통화 중 구두로 카드 비밀번호 탈취 | — | 공백(의도) |
| **T6** | 실물 카드를 휴대전화 뒷면에 태그하도록 지시 | — | 공백(의도) |
| **T7** | 카드 응답을 외부로 실시간 중계 |  ([R-23](rule-catalog.md#r-23) · [R-24](rule-catalog.md#r-24) 조건부) | **거래 보류** |
| **T8** | 인증 오류 화면으로 릴레이 시간 확보 | [R-24](rule-catalog.md#r-24) | **거래 보류** |
| **T9** | 대포폰이 카드를 흉내내고 탈취한 비밀번호 입력 | [R-23](rule-catalog.md#r-23) | **거래 보류** |
| **T10** | 원격지 ATM에서 현금 인출 승인 | [R-22](rule-catalog.md#r-22) · [R-26](rule-catalog.md#r-26) | **거래 보류** |

여러 룰이 동시에 걸리면 가장 강한 정책을 적용한다.

```
거래 보류  >  아웃바운드 콜  >  추가 인증  >  모니터링
```

**T3에서 이미 거래 보류가 가능하다.** 현금이 빠져나가는 T10보다 7단계 앞선다. 특히 태그 세션 룰은 27개 중 유일하게 인출이 완료되기 전에 발동한다.

**공백 3곳 중 T6이 가장 아프다.** 태그가 시작되는 순간을 단독으로 잡는 룰이 없어, 태그 진행 시점(T7)부터 조건부로 걸리도록 보완했다. T1은 통화 상태만 수집해 후속 룰의 조건으로 쓰고, T5의 통화 내용은 관측 대상이 아니다.

## 발화 근거

시점마다 어떤 데이터가 걸려 그 정책이 나오는지 정리한다. 데이터 이름을 누르면 정의로 이동한다.

| 시점 | 걸리는 데이터 | 판정 이유 |
| --- | --- | --- |
| **T1** | [통화 상태·시간](detection-device.md#dev-call) | 통화가 시작되고 지속 시간이 쌓인다. 통화 상태만으로는 단독 룰을 두지 않고 후속 룰의 조건으로만 쓴다. 비밀번호는 릴레이 경로로 넘어오지 않아 반드시 통화로 탈취해야 하므로, 장시간 통화는 이 공격의 구조적 필수 조건이다 |
| **T2** | [URL 검사(직접)](detection-device.md#thr-r-url-scan) · [도메인 등록 경과일](detection-device.md#thr-r-domain-age) · [리다이렉트 횟수](detection-device.md#thr-r-hops) | 가짜 스토어가 신생 도메인이라 위험목록 등재 판정이 침묵한다. 도메인이 등록된 지 얼마 안 됐다는 사실로 포착한다 |
| **T3** | [위협 앱 분류](detection-device.md#thr-i-category) · [인증서 해시](detection-device.md#thr-i-cert) · [위협 앱 표시명·패키지](detection-device.md#thr-i-name) | 은행 브랜드 이름을 쓰면서 서명 인증서가 정식 앱 목록과 다르다. 정식 앱을 변조한 게 아니라 별도 앱이라 앱 무결성은 정상으로 나오고, 인증서 대조가 유일한 근거가 된다. 2026년 신규 계열이라 진단명이 미등재로 확진 룰은 침묵하고, 위험도가 낮게 산정되어 사칭 분류 룰은 조건을 완화해야 걸린다 |
| **T4** | [NFC 최소권한 앱 여부](detection-device.md#thr-i-nfc-lowperm) · [과다 권한 목록](detection-device.md#thr-i-perms) · [모델·제조사](detection-device.md#dev-model) | 과다 권한 목록이 비어 있다. 비밀번호를 통화로 탈취하므로 앱이 문자·접근성·오버레이를 요구할 필요가 없어서다. 권한이 많을수록 위험하다는 통상 기준에서는 오히려 착해 보이는데, 이 빈 목록 자체를 위험 신호로 쓴다. 다만 NFC 리더 유틸리티도 같은 구성이라 보류까지 가지 않고 인증만 요구한다 |
| **T5** | [통화 상태·시간](detection-device.md#dev-call) | 통화가 유지되는 것만 보인다. 비밀번호는 카드 응답값이 아니라 사람이 키패드에 넣는 값이라 릴레이 경로에 없고, 통화 내용은 관측 대상이 아니라 이 시점은 비워 둔다 |
| **T6** | [거래 시점 NFC 태그 여부](detection-device.md#thr-r-nfc-at-txn) · [NFC 사용 모드](detection-device.md#thr-r-nfc-mode) · [장시간 태그 여부](detection-device.md#thr-r-nfc-long) | 태그 지시 단계다. 태그가 시작되는 순간이 릴레이의 시작인데 이 시점을 단독으로 잡는 룰이 없다 — 태그 세션 룰과 장시간 태그 룰은 거래 승인이 도달하거나 30초가 지난 뒤에야 확정 발화한다 |
| **T7** | [NFC 사용 모드](detection-device.md#thr-r-nfc-mode) · [장시간 태그 여부](detection-device.md#thr-r-nfc-long) | 카드 읽기 모드로 태그 세션이 진행 중이다. 확정 발화에는 거래 승인 요청이 태그 구간에 도달해야 해서 이 시점은 조건부로 둔다 |
| **T8** | [장시간 태그 여부](detection-device.md#thr-r-nfc-long) · [NFC 최소권한 앱 여부](detection-device.md#thr-i-nfc-lowperm) · [최근 하루 사용 시간](detection-device.md#thr-i-usage) | 단일 태그가 30초를 넘겼다. 카드와 단말은 4cm에서 즉시 통신하는데 릴레이는 인터넷 왕복 지연이 끼고 가짜 오류로 시간을 더 벌어야 한다. 태그 시간을 줄이면 릴레이 자체가 실패하므로 회피가 어려운 물리적 지문이다. 최소권한 앱·카드 읽기 모드가 함께 성립해 교통카드 충전이나 리더 유틸리티와 구분된다 |
| **T9** | [장시간 태그 여부](detection-device.md#thr-r-nfc-long) · [거래 요청 시각](detection-financial.md#fin-txn-time) · [NFC 거래 여부](detection-financial.md#fin-rf-txn) | 태그 세션이 열려 있는 동안 비접촉 거래 승인 요청이 도달했다. 릴레이는 거래가 진행되는 그 순간 카드가 태그돼 있어야만 성립하므로 이 겹침이 릴레이의 정의 자체다. 27개 룰 중 유일하게 인출이 완료되기 전에 발동한다 |
| **T10** | [ATM 위치](detection-financial.md#fin-atm-loc) · [접속 IP·위치](detection-device.md#dev-ip) · [카드 발급지](detection-financial.md#fin-card-region) · [근처 국가코드·로밍](detection-device.md#dev-roaming) · [통화 상태·시간](detection-device.md#dev-call) | 카드는 피해자 손에 있는데 인출은 원격지 ATM에서 일어난다. 두 위치가 물리적으로 이동 불가능한 거리이고 로밍도 아니다. 두 위치를 각각 다른 주체가 갖고 있어 단말·금융 데이터를 합쳐야만 판정된다. 여기에 30분 이상 통화가 유지된 상태로 비접촉 인출이 요청돼 통화 룰도 함께 걸린다 |

**네 시나리오 중 커버리지가 가장 좁다.** 백신과 원격제어 계열이 통째로 무력하다. 게다가 최소권한 앱·태그 세션·장시간 태그 세 룰은 새로 도출한 NFC 데이터에 의존해, 그 데이터가 없으면 커버가 URL 접속·인증서 대조·기기 위치 불일치 세 개로 줄어들고 T4·T7~T9 구간이 전부 공백이 된다.
